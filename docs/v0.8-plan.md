# v0.8 — nine fixes and features, plus the roadmap sweep

## Context

CAMusic has two independent playback paths: **Music Assistant** (this phone as a Sendspin player,
`SendspinAudioEngine` → `AudioTrack`) and **Navidrome/OpenSubsonic** (a local ExoPlayer queue).
They share one UI and almost nothing else, which is why most of what follows has to be answered
twice.

Nine things are being asked for. Eight are user-visible gaps; the ninth is "plan the rest of the
roadmap". They fall into five groups:

1. **Things the Navidrome path simply doesn't have** that MA does — continuous play. MA's
   `radio_mode` and `dont_stop_the_music` are *server* features, and both toast "needs Music
   Assistant" on the local path. Nothing generates a queue locally.
2. **Things where the data is already in the app and just isn't shown.** Bitrate and channel count
   are already parsed off OpenSubsonic (`SubsonicClient.audioFormat`). `music/artists/top_tracks`
   and `music/artists/similar_artists` are implemented in `MaRepository` with **zero callers**.
   `getArtistInfo2` is called with `count=0`, which explicitly asks Navidrome for *zero* similar
   artists.
3. **Things that are built but don't feel right.** Search fires only on the IME Search key, with
   no debounce anywhere in the tree. The lyrics pane snaps the active line two rows from the top
   with an un-animated 16→20sp font jump. The codec pop-up is functional but plain, and
   structurally fragile in a way that has already produced two separate layout bugs.
4. **Organisation.** Light Sync's transport and pairing settings are buried inside
   `SettingsSection.SERVERS`, and the remaining roadmap needs sequencing.
5. **A feature that is wired end to end and silent.** The MA player's DSP screen saves without
   error and changes nothing you can hear (§9). Both DSP calls swallow the server's error, and MA
   is already reporting the reason per track in a field this app parses and throws away.

The outcome: the standalone Navidrome backend stops being the second-class half of the app, the
player's audiophile surfaces — badge, pop-up, lyrics — match the design the rest of the app
already has, and the roadmap has an order behind it.

## 1. Continuous play on the Navidrome path

Two halves: an endless radio once the queue ends, and the seam between tracks.

### 1a. Local radio

Nothing generates a queue locally. `AppSettings.radioMode` already exists and is persisted; it is
just MA-only today — `LibraryViewModel.radioMode()` feeds `MaRepository.playOn`, and
`NowPlayingViewModel.toggleRadioMode` toasts on the local path. Make it one setting with two
implementations.

**New Subsonic bindings** in `subsonic/SubsonicClient.kt`, all absent today:

- `getSimilarSongs2(id, count)` — the primary seed; works off a track *or* an artist id.
- `getTopSongs(artist, count)` — the artist-level fallback.
- Reuse the existing `getSongsByGenre`, `getRandomSongs`, `getStarred2`, `getAlbumList2`.

**New `audio/LocalRadio.kt`** — a seeded generator with no UI of its own:

- Seed from the last-played `LocalTrack`; it already carries `scrobbleId`, which is the Navidrome
  id.
- A strategy ladder, first non-empty wins: `getSimilarSongs2(trackId)` →
  `getSimilarSongs2(artistId)` + `getTopSongs(artist)` → `getSongsByGenre(genre)` →
  `getRandomSongs(genre)`.
- Dedupe against a rolling history of the last ~200 ids and against the live queue, so a radio
  doesn't loop back on itself inside one session.
- **Offline:** when `LibraryViewModel` is in its Offline state, seed from `downloads.value` rather
  than the server, reusing the filter shape of `searchDownloads`.

**The hook.** `LocalPlayer` has no "queue running low" signal. Add one to the existing
`onMediaItemTransition` listener: when `mediaItemCount - currentIndex <= 2` and radio is on,
fetch ~10 more and `addToQueue` them. Topping up *ahead* of the boundary is what keeps ExoPlayer's
gapless intact — never wait for the queue to actually empty.

Give `PlayerOptionsSheet`'s "Don't stop the music" toggle the same generator instead of its
current toast.

### 1b. The seam between tracks

Gapless already works here because the whole queue is handed to ExoPlayer at once
(`LocalPlayer.setQueue`). Crossfade does not exist anywhere in the code, and is genuinely harder:
media3 1.10 has no crossfade, and a single ExoPlayer has one output, so an `AudioProcessor` can
fade but cannot overlap two tracks.

- **Phase A — "Smooth transitions".** A volume ramp out over the last N seconds and in over the
  first N, driven through the *existing* `applyGain()` volume path off the 250 ms position ticker.
  New setting `navCrossfadeSeconds`, 0 = off, 1–12. **Auto-suppressed when the queue is a single
  album**, because a fade is wrong for a segued record. Gapless stays the default and the setting
  says so.
- **Phase B — true overlapping crossfade.** Deferred to its own change. It needs a second
  ExoPlayer ping-ponged with volume ramps, which moves queue ownership out of one player and
  touches ReplayGain, the notification and the analysis tap.

**Files:** `subsonic/SubsonicClient.kt`, new `audio/LocalRadio.kt`, `audio/LocalPlayer.kt`,
`ma/LibraryViewModel.kt`, `ui/viewmodel/NowPlayingViewModel.kt`, `ui/screens/PlayerOptionsSheet.kt`,
`data/AppSettings.kt`, `ui/screens/SettingsScreen.kt`.

## 2. The codec badge and its pop-up

### 2a. Badge text

`StreamQuality.label` renders `FLAC · 96/24 · 1411k` today. The change lives in
`audio/StreamQuality.kt` alone — every call site reads `label` or `shortLabel`:

- Separator `·` → `•`.
- Bitrate in human units: ≥ 1000 kb/s becomes `3 Mb/s` (one decimal, trailing `.0` dropped),
  otherwise `805 kb/s`.
- Result: `FLAC • 96/24 • 3 Mb/s`, `FLAC • 44.1/16 • 805 kb/s`, `AAC • 256 kb/s`.
- `shortLabel`, which track rows use, stays compact — no bitrate, no bullets.

The rate keeps its decimal: `44.1`, not `44`. `khz()` already renders one decimal and 44.1 kHz is
the real number.

**Where the bitrate comes from.** Navidrome already parses `bitRate`, `samplingRate`, `bitDepth`,
`channelCount` and `replayGain` in `SubsonicClient.audioFormat` — nothing new is needed. Add
`size` parsing so a bitrate can be derived (`size * 8 / durationSec / 1000`) when a server omits
`bitRate`.

MA reads `bit_rate` from `provider_mappings[].audio_format` and from `streamdetails`, but
providers routinely leave it 0 for FLAC. Show it when it is greater than 0 and omit the segment
otherwise. While here, reconcile the parse asymmetry: MA defaults `bit_depth` to 16 and Subsonic
defaults it to 0. Default both to 0 and let the UI say "unknown" rather than claim CD depth.

### 2b. The pop-up must never move the album art

The cover is the **only `weight(1f)` child** of the Now Playing `Column`, so every dp a sibling
gains, the cover loses. Two separate bugs have already been fixed here, and the comments in
`NowPlayingScreen.kt` are the only record of both:

- Drawn inline, the card grew the badge's own `Column { chip; PlayButton }`, which grew the
  transport `Row`, which shrank the art.
- Drawn as a *focusable* `Popup`, window focus put the activity through its soft-input resize path
  and the art shrank again.

The current non-focusable `Popup` is the third attempt. Rather than debug a fourth, remove the
class of bug: render the detail as an **overlay sibling inside the screen's root `Box`**, hoisting
`showDetail` up to `NowPlayingScreen` and `NowPlayingOverlay`. Both already have a root `Box`, and
this is exactly how `NowPlayingSheet`, `PlayerOptionsSheet` and `MediaActionsSheet` are already
drawn. An overlay sibling in a `Box` cannot change any sibling's measured size, and there is no
second window to interact with insets or focus.

Fix the same latent bug in the sleep-timer popup in `NowPlayingPanels.kt`, which is still
`focusable = true`.

Add the entry and exit the pop-up has never had: `AnimatedVisibility` with `Motion.effects()` for
the scrim fade and `Motion.spatial()` for a scale-up from the badge. The house rule in
`design/Motion.kt` holds — never alpha on a spatial spec, never position on an effects spec.

### 2c. Make the pop-up beautiful, cohesive and detailed

Rebuild `QualityDetailCard` against `LocalPalette` rather than `LocalAccent` alone, so it is lit
by the album the way the rest of the screen is:

- A vertical gradient from `Ink2` to `palette.accent.a(0.10f)`, a 1dp `accent.a(0.35f)` border and
  a `CastGlow` in the accent underneath — the glass-plus-coloured-shadow language `GlassCard`,
  `QualityPill` and `SegmentedToggle` already speak.
- A header strip: a 40dp album thumb via `rememberArtRequest` plus title and artist, so the card
  is visibly about *this* track.
- `SectionLabel` eyebrows, and `MonoFont` on every number so digits don't jitter.

Three blocks of content:

| Block | Rows |
|---|---|
| **Format** | Playing / Source (the existing `QualityRow`) · transcode verdict · codec vs container (`suffix` vs `contentType`) · channels · file size · duration |
| **Output** | bit-perfect on/off · device output rate from `FormatNegotiator.deviceOutputQuality()` · an explicit "resampled 44.1 → 48 kHz by the Android mixer" line when they differ · MA's DSP state from §9b · exclusive-mode state once §8 lands |
| **Level & origin** | ReplayGain (the existing three-state logic) · **MA loudness readout** — `loudness`, `loudness_album` and `volume_normalization_gain_correct` sit in `StreamDetails` and are parsed nowhere today · provider / Navidrome / Offline, plus the local path · year, genre, composer, disc and track |

Plumbing: extend `StreamQuality` with `channels` and `sizeBytes`, and assemble a `QualityDetail`
model in `NowPlayingViewModel` so the card stays a dumb renderer.

**Files:** `audio/StreamQuality.kt`, `subsonic/SubsonicClient.kt`, `ma/MaModels.kt`,
`ui/screens/NowPlayingScreen.kt`, `ui/screens/NowPlayingOverlay.kt`,
`ui/screens/NowPlayingPanels.kt`, `ui/viewmodel/NowPlayingViewModel.kt`.

## 4. Smoother, better-timed lyrics

`ui/screens/LyricsPane.kt` is 165 lines, and every problem is inside `SyncedLyrics`.

**Centring.** Today `scrollToItem(active - 2)` puts the sung line two *rows* from the top, and row
heights vary. Replace it with real centring computed off `listState.layoutInfo`: take the active
item's `offset + size / 2`, subtract the viewport centre, and `animateScrollBy(delta,
Motion.spatialSlow())`. Give the list top and bottom `contentPadding` of half the pane height so
the first and last lines can actually reach the middle. Keep the jump-on-seek branch
(`abs(active - previous) > 4` → instant `scrollToItem`); the comment explaining why is correct.

**Size and weight.** 16sp → 20sp currently flips instantly, which forces a relayout rather than a
scale. Drive a per-line `activeness: Float` through `animateFloatAsState(Motion.effects())` and
use it for scale, alpha and a colour `lerp` between `TextMuted`/`TextFaint` and the album accent.
Scale via `graphicsLayer` off a fixed base size so the *layout* height never changes — that is
what removes the shudder. Add a distance falloff on `|i - active|` so the pane reads as a focus
lens, and honour reduced-motion.

**Timing** — currently close, and these are the last few percent:

- Add a **lead**: derive the index from `positionMs + LEAD_MS`, around 180–220 ms, so the scroll
  *starts* just before the line lands. The highlight currently flips exactly on the stamp, which
  reads as late once a scroll animation sits on top of it.
- Add a persisted **lyrics offset**, ±2 s, in Settings, because provider LRCs vary.
  `StructuredLyrics.kt` already applies OpenSubsonic's per-set `offset`; the LRC parser in
  `MaModels.kt` ignores `[offset:]` metadata tags, so handle those too.
- Raise `PlayerPositionTracker.TICK_MS` from 500 ms to 250 ms, matching
  `LocalPlayer.POSITION_TICK_MS` and the Sendspin path. Lyrics on a remote MA speaker are
  currently up to half a second late for this reason alone.
- Don't let `active` land on a blank line. Blank lines render as a bare `Spacer` but still hold an
  index.

**Files:** `ui/screens/LyricsPane.kt`, `ui/viewmodel/PlayerPositionTracker.kt`, `ma/MaModels.kt`,
`data/AppSettings.kt`, `ui/screens/SettingsScreen.kt`.

## 5. Album screen — an About section, then related albums

`AlbumDetailScreen` is one screen for both backends; the ViewModel branches on
`provider == SubsonicClient.PROVIDER`. The `LazyColumn` ends at the track list today. Add two
sections after it, each loaded lazily so neither blocks the main load.

**About this album.** Notes already exist on Navidrome through `getAlbumInfo2.notes` and the
`AlbumNotes` composable. On the **MA path they are never fetched even though the data is parsed** —
`MaItem.description` reads `metadata.description ?? metadata.review`. Wire it up. Beside the prose,
a facts grid: release year, genres, disc count, track count, total duration, and the formats
present in the track list, derived from `track.audioFormat`. `getAlbumInfo2` currently discards

**More from this artist.** MA: `music/artists/artist_albums`, already implemented. Navidrome:
`getArtist(artistId)` — a Subsonic album carries `parentId` as the artist id, so no name matching
is needed; on MA fall back to the resolution `ArtistDetailViewModel.resolveRef` already does.
Exclude the album being viewed.

**When the artist has nothing else**, in order:

1. Similar artists' albums — MA `music/artists/similar_artists`; Navidrome `getArtistInfo2` with a
   real `count` (see §6), then `getArtist` per hit.
2. Same-genre albums — Subsonic `getAlbumList2(type=byGenre, genre=…)`; MA `music/search` on the
   genre name.
3. Nothing. Hide the section — never render an empty shelf.

Fix in passing: `SubsonicClient.albumItem` never parses genre, so the Navidrome metadata line is
missing it and the genre fallback above would have nothing to work with.

Render as a horizontal `LazyRow` of cover tiles reusing `rememberArtRequest`, `sharedArt` and

never block the screen. Keys must stay `section:index:itemId` — MA numbers library items per media

## 7. Live search

`SearchField` fires only on the IME Search key; `onValueChange` just stores text. There is **no
debounce anywhere in the tree** — every existing site is a hand-rolled cancel-previous-job, and
`LightSyncViewModel.patchDebounced` is the closest thing to a utility. `kotlinx.coroutines.flow.debounce`
is unused.

Make `_query` the source of truth for searching in `LibraryViewModel`:

```kotlin
_query.debounce(220).map { it.trim() }.distinctUntilChanged()
      .filter { it.length >= 2 }
      .flatMapLatest { q -> flow { emit(Loading); emit(search(q)) } }
```

`flatMapLatest` is the important half. It cancels the in-flight request when the next keystroke
lands, which is what stops results arriving out of order and what makes the field feel instant.

- Keep the IME Search key as an immediate trigger that bypasses the debounce.
- **Show something on the first keystroke.** While the network call is in flight, filter what is
  already in memory — browse caches, and downloads through the existing `searchDownloads` — then
  merge server results when they land.
- Keep a small LRU cache of query → results so backspacing is instant and doesn't re-hit the
  server.
- Loading is a slim indeterminate line above the results, never a spinner that replaces content
  already on screen.
- Keep live limits at 30 per type; raise them only on an explicit submit.
- A blank query still calls `clearSearch()`, and the `searchDepth` restore-on-back behaviour must
  keep working.

Lift the debounce into a small shared helper so `LightSyncViewModel`, `SpeakersViewModel` and the
volume slider can adopt it later.

**Files:** `ma/LibraryViewModel.kt`, `ui/screens/LibraryScreen.kt`, new `util/Debounce.kt`.

## 8. The rest of the roadmap

### 8a. Audiophile core

- **24-bit on the Navidrome path.** `LocalPlayer` never reads `AppSettings.bitPerfect24Bit` at
  all; only `SendspinAudioEngine` honours it, so a 24/96 FLAC from Navidrome plays through
  ExoPlayer's default 16-bit sink. `setEnableAudioFloatOutput(true)` was tried and reverted —
  audible distortion at 44.1/16 on a 48 kHz device — so re-enable it **behind the bit-perfect
  setting and only when the source is ≥24-bit**, the same rule `SendspinAudioEngine` already
  applies.
- **Native AAudio exclusive I24**, the largest single audio item. `app/src/main/cpp/` is written,
  `externalNativeBuild` is commented out, and `flac_decode()` is a non-functional skeleton — it
  calls `process_single()` twice with a `nullptr` read callback, and the ring buffer is byte-level
  rather than frame-level. Enable the NDK build, finish the decoder, add a JNI bridge, route to it
  when 24-bit is requested with a graceful fallback to `AudioTrack`, and add an EXCLUSIVE state to
  the pop-up from §2.
- **Gapless on the MA path.** The approach is already chosen in `v0.5.0-analysis.md`: after
  `stream/end`, watch for `server/state` with `playback_speed: 0` inside a short window to tell a
  track boundary from a pause. The earlier attempt — holding the read-ahead buffer — broke the
  pause button; don't repeat it.
- **MA player config from the app.** Gapless (disabled / standard / smart) and crossfade are MA
  per-player settings. `MaRepository.playerConfigEntry()` already reads an arbitrary `ConfigEntry`
  with the server's declared `options` and handles protocol-wrapped key names. This is a UI job.
- **MA loudness readout** — lands with §2c.
- **Navidrome crossfade** — lands with §1b.
- **USB DAC routing** is partly there already (`preferredAudioDeviceId`, `OutputDevicePicker`,
  `LocalPlayer.setPreferredDevice`). What's left: show the DAC's supported rates and depths, and
  say when the Android mixer is resampling.

### 8b. Settings must reflect all of it

Most of this surfaces in the `AUDIO` section: an exclusive-mode toggle with a device-capability
readout, max sample rate, smooth transitions / crossfade seconds, continuous play (no longer
MA-only), lyrics offset, alongside the existing bit-perfect and output-device controls. House
style holds — every control gets a `TextFaint` `bodySmall` explanation directly beneath it.

### 8c. Feature completion

- **Version picker.** `music/tracks/track_versions` and `music/albums/album_versions` are
  implemented with zero callers. UI only.
- **Cross-device resume.** `getPlayQueue` / `savePlayQueue` are implemented with zero callers.
  UI only.
- **Warm reconnect.** `client/goodbye` with `reason: "restart"` on backgrounding. Reverted once
  because it fired mid-song; it must fire only while idle.
- **A Downloads screen** with sort, search, retry and a storage breakdown, replacing the Library
  shelf.

### 8d. Platform

- **Android Auto.** media3-session is already a dependency and the `MediaSession` already exists;
  the work is a manifest declaration and a browse tree.
- **A Glance home-screen widget** and a **Quick Settings tile** for Light Sync.
- **A release keystore and CI signing.** Releases are cut locally because a CI runner generates a
  fresh debug keystore every run and Android refuses an update whose signer changed.

### 8e. Housekeeping

- **Room** for the download index, which is a JSON file rewritten in full on every change.
- **Instrumented tests.** The ~174 unit tests cover protocol, clock and parsing; nothing covers
  the audio path, the service lifecycle or the UI.
- **Crash reporting** — ACRA or similar, self-hosted.
- **The six files over 700 lines**, and the ~184 `runCatching` sites that swallow a failure
  without recording it. `NowPlayingScreen` and `NowPlayingOverlay` are near-duplicates — `TopBar`,
  `TransportIcon`, `TimeText`, `fmtTime`, `OfflineBanner` and `IdleNotice` are copy-pasted into
  both — so every player change has to be made twice, including §2's.

## 9. The Music Assistant DSP does nothing to the audio

The screen is complete. `DspScreen.kt` is 858 lines, `DspModels.kt` mirrors MA's `DSPConfig`, and
`config/players/dsp/{get,save}` plus `config/dsp_presets/{get,save,remove}` are all in
`MaRepository`. Bands, tone control, preamp, gains, limiter and presets round-trip. It just isn't
audible.

**This is a diagnosis-first item.** The plan below fixes what is wrong regardless, and puts an
ordered procedure behind the part that needs a live server. Don't skip to a fix: this repo has
precedent for exactly this failure mode — the Corrections section of `improvement-roadmap.md`
records that all five MA playlist commands were the wrong names, "accepted and ignored", so the
feature "had never worked against any server".

### 9a. The app is hiding the server's answer — fix this first

Both DSP calls swallow failures identically:

```kotlin
val res = runCatching { api.sendCommand("config/players/dsp/save", …) }
    .getOrNull()?.jsonObject ?: return null
```

A rejected save returns `null`, and `DspViewModel.save()` reports **"DSP saved but server didn't
confirm"** — which reads as a cosmetic wobble rather than a refusal. `config/players/dsp/save` is
**admin-only on the server**, so a non-admin MA login would be refused every single time and the
app has been saying it half-worked. The read side is worse: `getDspConfig` returning `null`
becomes `DspConfig()` in the ViewModel — all defaults, disabled — so an error renders as a clean,
empty, entirely plausible EQ.

Let `MaApiException` propagate; the ViewModel already has `try/catch` around both. Show the
server's own message and code, and distinguish "refused" from "empty". This alone may name the
bug, and nothing else here should be attempted before it has been run once.

### 9b. MA is already saying why, and the app discards it

`streamdetails.dsp` is a map of `player_id → DSPDetails`, and the app parses it purely for
`output_format`. The KDoc directly above that loop even records that a `dsp` entry *"whose `state`
is disabled still carries an output format"* — so `state` is read and dropped on the floor.

That field is the server's own diagnosis, per track. Parse `DSPDetails.state`, along with its
`filters` list and `output_limiter`, and surface it twice: as an Output row in the pop-up from
§2c, and as a banner at the top of the DSP screen naming the reason MA gives.

Two states matter especially. MA disables per-player DSP when a player is **part of a sync group**,
because a group shares one stream job and per-player filtering can't apply; and when the output
format is one it won't filter. Either produces exactly the reported symptom, and neither is
fixable client-side — but both are explainable, and an EQ that says why beats an EQ that just sits
there.

### 9c. Rule out the app's own bypasses

Three paths route audio around MA entirely, and DSP cannot apply on any of them:

| Path | Where |
|---|---|
| **"Play at original quality"** — when MA would convert, the app streams straight from Navidrome | `AppSettings.preferOriginal`, gated by `FormatNegotiator.canStreamUntouched` |
| The **Navidrome backend** — a local ExoPlayer, with MA not in the path at all | `audio/LocalPlayer.kt` |
| **Downloads** — bytes off local storage | `download/DownloadManager.kt` |

This is the most likely everyday cause, and it is entirely silent: the setting is on, the track
qualifies, MA is bypassed, the EQ does nothing, and nothing anywhere says so. The DSP screen
should detect the active path and either disable itself with an explanation or offer to turn the
bypass off. The conflict is real and unavoidable — bit-perfect original bytes and server-side DSP
are mutually exclusive by definition — so present it as a choice, not a fault.

### 9d. Verify the wire format against MA 2.9.9

Only once 9a is showing real errors. Check `DspParse.toJson` field by field against MA's
`DSPConfig`, `ParametricEQFilter`, `ToneControlFilter` and `DSPDetails` schemas. Two specifics:

- `toJson` **omits `filters` entirely when the list is empty**. If MA merges rather than replaces,
  clearing every band would leave the old chain in place server-side.
- `replaceFilter` ends in `distinctBy { it::class }`, capping the chain at one EQ and one tone
  filter. That matches this UI, but MA's `filters[]` is an ordered chain that may hold several, so
  a config authored in MA's own interface gets silently flattened on the next save from here.

### 9e. Live-apply

Both `DspViewModel` and `MaRepository.saveDspConfig` claim in their KDoc that MA "applies it live —
no playback restart needed". Verify it. If a filter change only takes effect on the next stream
job, the save has to offer to restart the current stream at its position, or the user presses
Save, hears nothing, and concludes the feature is broken even once it works.

### The procedure, in order, on a device against a real MA

1. Land 9a, save any change, and read the actual error. If it says admin, the fix is a clear
   message plus a note in Settings, and this is done.
2. Set the same EQ from **MA's own web interface** on the same player. If that is also silent, the
   problem is server-side or in MA's Sendspin provider, not here — and the honest answer is 9b's
   banner, not more client code.
3. Check whether the phone is in a sync group, and whether "Play at original quality" is on.
4. Compare `streamdetails.dsp[<playerId>].output_format` against `audio_format` with a large,
   obvious filter enabled. If MA is filtering, it is doing work here.

## Risks, and what is still open

- **Crossfade Phase B** is deliberately deferred. If true overlapping crossfade is wanted sooner
  it is its own change, because it moves queue ownership away from a single ExoPlayer.
- **Similar artists on Navidrome** depend on the server having last.fm metadata configured. Every
  new section must hide itself rather than render an empty shelf.
- **The duplicated player screens** mean §2 has to be written twice. Extracting the shared parts
  first is worth considering if §2 grows.
- **§9 may not be an app bug at all.** If MA's Sendspin provider doesn't run the DSP chain for
  Sendspin players, or the phone is grouped, no client change makes it audible, and the
  deliverable becomes an honest explanation instead of an EQ that pretends. Either outcome is a
  real result. No fix should be written before step 1 of the procedure has been run.
- **Native AAudio** carries genuine device fragmentation risk — not every device allows exclusive
  mode — and an NDK toolchain requirement in CI. That is why it stays last.
