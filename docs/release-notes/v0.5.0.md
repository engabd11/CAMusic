v0.5.0 - CAMusic: a smooth library, a motion layer, and a theme you can pick
First stable build. Formerly Sendspin.

## Install
1. Download **camusic-0.5.0.apk** below (Android 12 / API 31+).
2. Allow **install from unknown sources**, then open it. Installs over 0.4.x (versionCode 27) — the signing key is unchanged, so your server, credentials and downloads survive.

The app is now **CAMusic**, with a new mushroom mark. The package id is deliberately
unchanged (`com.engabd.sendpin`), because changing it would make this a different app
to Android: a fresh install, and everything you had configured gone. The Sendspin
*protocol* keeps its name throughout — it is what Music Assistant calls the transport,
and it is not the app.

This is also the first release built in **release** configuration rather than debug.
Every previous build shipped with Compose composition tracing on, R8 off and
`debuggable` set, which suppresses most of ART's optimisation. That alone accounted for
a good share of what the app felt like.

## Scrolling

Measured on a Galaxy S23 at 120Hz: **0.20% janky frames, 95th percentile 8ms** against
an 8.33ms budget, zero missed vsyncs.

Six things were making the library work harder than it needed to. Lazy items had no
keys and no `contentType`, so a grid mixing category cards, cover tiles, list rows,
headers and skeletons could not recycle a scrolled-off row into a slot of a different
kind. Each visible row stood up three of its own flow collectors, torn down and rebuilt
as rows recycled. Five media-type tests built a fresh `Set` per call, the worst of them
inside a count over the whole list. The seven root shelves were seven separate flows, so
opening the library rebuilt the grid seven times as they loaded. `MaItem` compared by
instance, so every reconnect rebuilt every visible row for data that had not changed.
And every cover tile carried an elevation shadow, drawing something invisible against
true black.

A **baseline profile** now ships with the app, so the code the library touches is
compiled ahead of time instead of being interpreted until the JIT catches up.

## Motion

The app had none: screens cut, lists popped, and sheets appeared fully formed.

Tapping a cover now flies that artwork into the album screen's hero. Detail screens push
in from the right and leave the way they came, so the back gesture undoes the push
rather than dissolving it. Shelves and the downloads list animate their items. Sheets
slide up on the same spring they already used to be thrown away with. Predictive back is
on.

## Appearance

OLED black with an album-derived accent is still the default and still what the app is.
It is no longer the only option: **Settings → Appearance** now offers OLED black, a
softer Dark for LCD panels, Light, or follow-system — and an accent taken from the album
art, from your wallpaper (Material You), or fixed to a colour you pick.

## Fixes

- **Crash on first clean start.** An init block sat above the properties it used, so a
  collector firing during construction hit a null field. It only ever showed on the run
  where connecting finishes during onboarding, before Now Playing is first composed.
- **A corrected Navidrome address lost the race with the wrong one.** Fixing a typo left
  the app reporting an error for the address you had already fixed until it restarted.
- **The notification and lock screen scrubber sat at the end of the song.** An unknown
  duration was published as 0, which to Android is a zero-length track.
- **The DSP panel is a sheet on the player** rather than a screen of its own, so you can
  see and hear what you are tuning.
- Album track rows show the codec — `FLAC 48/24`, `MP3 320k`.
- Tapping the tab you are already on returns to the top of that section, and the tab bar
  stays lit when you are inside an album.
- The minimised player is twice as tall and carries skip buttons.
