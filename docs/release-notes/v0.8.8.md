v0.8.8 - the lights become a room, and Jellyfin actually plays
Stable build of CAMusic for Android.

Two big pieces and ten reported fixes. The headline is that direct Philips Hue
light sync now renders the room as one field rather than as a set of independent
lamps, and that held notes light something at all.

## Light sync

**A long vocal used to fade the room out.** Measured on the previous build, a
sustained vocal over one second took the average brightness from 0.342 to 0.335.
That is not "too dim" — it is the wrong direction, and it explains why turning
reactivity up never really fixed it: you were compensating for a decay with a
global lift.

Three mechanisms were each individually right and collectively fatal for held
notes. Onset detection deliberately gates out narrowband material, so tonal
content cannot earn phantom flashes. The per-bin attack measure is taken against
a baseline a held note settles into, so a drone does not strobe. And a lamp
averages roughly seven of sixteen melbank bins, so a vocal occupying two or three
of them arrived at about a third of its real height. Nothing was aware of the
other two, so between them nothing was left.

- **A sustain layer.** Fires exactly where the event layers are silent: inverted
  onset width, mid presence, and chroma stability — which is what separates a
  held pitch from a cymbal wash. Damped against live transients so a beat and a
  bloom never claim the same moment, and slow enough to bloom rather than pulse.
  It enters as a brightness target rather than a flash, so it passes through the
  smoothers and stays well under both the eye-safety limiter and the
  Entertainment API's 12.5 Hz effect ceiling.
- **Neighbouring lamps share a drive.** A Gaussian kernel over the entertainment
  area's real 3-D positions, row-normalised so it redistributes the room's energy
  and can neither brighten nor dim it. Applied to the drive and never the output,
  so beat flashes and travelling wavefronts keep their punch — and being purely
  spatial it has no temporal memory, so it cannot shift the timing. There is a
  test asserting the frame each lamp peaks on is identical with coupling on and
  off.
- **Colour drifts in three dimensions.** It was a function of the left-to-right
  axis alone, so two lamps at the same width and different heights were always
  the same colour however far apart they were.
- **Height blends between bands** instead of snapping to one of five, so two
  lamps a hand's width apart no longer follow entirely different parts of the
  spectrum.
- **Mid content is filled properly.** A lamp now reads the peak of its slice as
  well as the mean, and per-band absolute loudness reaches every intensity rung.
- **Two of the six advanced sliders were doing nothing.** `Loudness` and
  `Contrast` were read only by the Extreme rung. Both now work everywhere, and a
  new **Cohesion** slider controls how tightly the room binds together.
- **The sliders no longer judder.** Each pointer move used to write to storage,
  which recomposed the whole screen sixty times a second. Live values now go
  straight to the engine and only the released value is saved. Every slider has a
  reset, and there is a Reset all.

Three bridge fixes: a reconnect after a Wi-Fi drop no longer silently loses each
lamp's colour gamut; starting sync no longer *takes* an entertainment area that
the Hue app or an HDMI Sync Box is already using, which the Entertainment API
allows only one of; and a height-blend edge case at the top of the room.

## Music Assistant player

The Sendspin player now runs on ExoPlayer with Oboe output, replacing the
hand-built decoder pipeline. That is what makes direct Hue sync work for Music
Assistant playback — the analysis tap sits in ExoPlayer's render chain, so it
sees MA audio now too.

**Volume follows whatever is actually making the sound.** The hardware rocker
reached nothing before: the on-screen slider moved a speaker in another room
while the buttons moved this phone's silent output. When this phone is the MA
player, the player volume *is* the phone's media volume — one number, not three.

- **Radio stations and podcasts** in the library, with the same motion as the
  other categories.
- **Podcasts play.** Tapping one did nothing at all before — and because
  "Continue listening" is filled entirely with podcasts and audiobooks, every
  tile on that shelf was a dead tap.
- **Player settings live with the server.** Name, stream format, gapless and what
  to ask the server for are on the Music Assistant server's own card, so the
  server, its library and the player are set up in one place.

## Jellyfin

**Playback was broken outright.** The stream URL sent `static=true` to an
endpoint where that parameter does not exist, so the request arrived carrying no
container profile and the server could neither direct-play nor pick a sensible
transcode. Every track in a queue came from the same template, so one bad URL
presented as a whole album flicking past in a couple of seconds.

Also fixed: two phones no longer fight over one session; the server's "Now
Playing" no longer goes stale after a minute; resume positions are reported
instead of always zero; cover art works on servers with anonymous image access
disabled; and there is a music-library picker for servers with more than one.

## Everywhere else

- **Speaker sync offset** showed a dash between two buttons that silently did
  nothing on any non-Sendspin speaker. It now falls back to Music Assistant's
  generic control, hides the row where neither exists, and stops re-asking the
  server every five seconds forever.
- **Pulling the mini player up** now animates, on the same spring as pulling it
  down, and the bar can be dragged as well as tapped.
- **One player at a time is enforced**, not assumed. Starting a local track while
  Music Assistant was playing to this phone left both decoding into the same
  output.
- **Onboarding** asks for notification permission with a reason instead of cold
  before the first screen, adds the battery-optimisation step the background
  connection depends on, and skips the Music Assistant speaker page for people
  who did not choose Music Assistant.

## Under the hood

One shared HTTP client with a cache, a real User-Agent and sane timeouts replaces
six independently built ones — the download manager had no timeouts at all, so a
stalled download hung forever. Three separate five-second loops were each fetching
the same two Music Assistant commands with no shared cache; that is now one,
cutting steady-state traffic by roughly two thirds. Artist catalogue loading was
one request per album in sequence — forty serial round-trips for a forty-album
artist — and is now a bounded parallel fan-out.

526 unit tests, lint and a debug build all pass. As with every release so far,
none of it has been run on a device.
