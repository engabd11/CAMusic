v0.2.6 — smooth seekbar, responsive skip, and the v0.2.5 fixes
Debug build of Sendspin for Android (work in progress).

## Install
1. Download **sendspin-0.2.6-debug.apk** below onto your Android device (Android 12 / API 31+).
2. Allow **install from unknown sources** when prompted.
3. Open the APK. Installs over 0.2.x (versionCode 11).

> **If you tried v0.2.5 and it refused to install** — that release was signed with a
> different key than every release before it, and Android rejects an update whose
> signer changed ("package conflicts with an existing package"). Nothing was wrong
> with your phone. This build is signed with the original key again, so it installs
> straight over 0.2.4 with no uninstall needed. See *Notes* for the details.

## What's new since v0.2.4

This release carries the eleven device-testing fixes that were meant to ship as
v0.2.5, plus the seek and skip work that landed separately — the two had gone into
different branches, so neither build had everything. They are merged here.

### Playback position and seeking

**The seekbar is smooth now.** Position used to come from a 2-second poll with a
naive `pos += 250` interpolation between polls, so the bar advanced in visible
lurches. It is now driven by a server-anchored engine: a 500ms local ticker
forward-projects from the last server anchor using the wall-clock delta, with
playback speed factored in. The bar no longer depends on network round-trips, and
the poll relaxes from 2s to 5s because position no longer rides on it.

**Seeking no longer snaps back.** After you release the bar it holds your target
position until the server position catches up (within 2s), instead of visibly
jumping back to the old spot during the round-trip. Seeks are also clamped to
`[0, duration - 1s]`, so dragging to the very end no longer reads as "skip to next
track" to Music Assistant.

**Rapid skips respond immediately.** Tapping skip repeatedly fired one Music
Assistant command per tap with overlapping refreshes, which stalled the next song by
several seconds. Skips are now guarded so rapid taps fire a single command, position
snaps to 0 optimistically before the server confirms, and bursts of player/queue
events coalesce into one refresh instead of triggering a full re-poll each.

### From the v0.2.5 set

**Sleep timer** did nothing you could see — it cycled 15/30/45/60 silently, so a
running timer and a dead button looked identical. It now opens a picker
(5/15/30/45/60/90), shows a live countdown beside the chip, and can be cancelled.
The countdown runs off a wall-clock deadline, so it stays honest across a doze.

**Queue.** A row is the track, so tapping one plays it. Reordering moved to a grip
on the right: hold it and the row follows your finger, with the list opening up
around it; a single move is sent when you lift. Remove is a control on the row
instead of a fold-out menu.

**Queue no longer scrambles when you play from it.** Every queue command used to
drop the panel to a spinner, losing the scroll position and re-collapsing every
row. Refreshes are now silent when a list is already up, a failed refresh keeps the
good list, and jumping to a track doesn't re-fetch the items at all.

**Swipes.** Swiping up on Now Playing brings the queue over it. The queue and
player-options sheets own their drag-to-dismiss and consume it, so a swipe aimed at
a sheet no longer drags the whole player down behind it. Swiping down on the player
itself still minimizes it.

**Library artwork.** Music Assistant serves `/imageproxy` from its *stream* server —
a different port from the API — and double-encodes the path. The app was building
singly-encoded URLs against the API port, so every cover that wasn't already a
public URL came back blank, which is why only podcasts had art. URLs are now built
MA's way, and the image loader probes the shapes MA has shipped (the `?path=` query
form and the newer opaque `sha256` id, on either port), remembering whichever the
server answers. Proxy responses also get a long cache lifetime, so covers stop
re-fetching on every scroll.

**Codec badge.** Playing quality is now the negotiated Sendspin output — the same
48/16 the Settings screen reports — rather than the queue's stream details, which
describe the source file. Locally decoded playback falls back to the phone's own
ceiling. The detail panel is a popup pinned to the middle of the window, so opening
it no longer shoves the transport row apart.

**Light Sync** listed every `hue_music_sync` device as an entertainment zone,
including the library entity, whose controls were all dead. A zone now has to carry
a sync switch.

**Source badge** read the media item's own provider, which is always `library` — so
Navidrome-backed tracks claimed to come from MA. It now reads the stream details'
provider, falling back to the item's provider mappings.

**Settings.**
- The Home Assistant long-lived token is sealed once saved: shown as dots, greyed
  out, and replaceable only as a whole.
- **Disconnect** is red.
- A new **Library** section picks the backend; choosing Navidrome greys out
  Speakers and Lights, both of which run through Music Assistant. The Library tab's
  own toggle is gone, so there is one place to set it.
- About reads the version from the build instead of a hand-typed string that had
  been stale since 0.1.3.

## Known gaps
- Playing a Navidrome track *directly* (the "play at original quality" path, or the
  Navidrome backend) decodes on the phone through a local player that Now Playing
  doesn't reflect — the badge and transport still show the Music Assistant queue.
- Dragging a queue row to the very edge of the list doesn't auto-scroll; long moves
  need two drags.

## Notes
- Unsigned **debug** APK (debuggable, not minified) for testing.
- Version 0.2.6 / versionCode 11. Logcat tag: `SendspinClient`.
- **On the v0.2.5 install failure.** "The debug keystore" is not one shared key —
  each machine generates its own at `~/.android/debug.keystore`, and a CI runner
  starts empty, so it signs with a brand-new throwaway key every run. v0.2.5 was the
  first release published by GitHub Actions, signed `03cdee29…`, while v0.1.0–v0.2.4
  were built locally and all signed `21b01f0f…`. Android refuses an update whose
  signer changed, which is the "conflicts with an existing package" error. Releases
  are cut locally again, and the CI workflow no longer publishes them.
