Stable build of CAMusic for Android.

## Install
1. Download **camusic-0.7.1.apk** below (Android 12 / API 31+).
2. Allow **install from unknown sources**, then open it. Installs over 0.7.0 (versionCode 30) — same signing key, so your servers, credentials and downloads survive.

One fix on top of [v0.7.0](v0.7.0.md). Everything in that release — Light Sync straight
to the Hue Bridge and all of it — is unchanged.

## Scrolling the library down killed the app

Open the Library tab on a Music Assistant server, scroll the root past the shelves, and
the app closed. It was not a slow list or a memory problem: it was a lazy list being
handed two items with the same key, which Compose treats as unrecoverable and throws on
the moment both are composed together.

The keys were `provider|itemId`, which reads as though it identifies a media item and
does not. A library item's own provider is always `library`, and Music Assistant numbers
library items **per media type** — so album 5 and track 5 are both `library|5`. Any list
holding more than one kind of thing can collide.

"For you" is that list. It is the only shelf built from more than one answer:
`music/recommendations` returns folders — recently played, favourite artists, random
albums — which the app flattens into a single row. The folders overlap on purpose, so
the same album arrived two or three times over. That shelf is fifth of seven, which is
why the crash needed a scroll to reach and looked like it was about the bottom of the
list rather than about one shelf in it.

Two changes, at both ends of it:

- Every list in the library is now keyed by **index as well as item**, so no answer from
  any server can make two keys collide. This is what the album, artist and playlist
  screens have always done — their comments call a duplicate key a hard crash — and the
  library was the screen that had not been brought over.
- "For you" is **deduplicated** as it is flattened, on provider *and media type* and id.
  An album that is both recently played and a favourite artist's is one tile now, not
  three, which is what the shelf was meant to look like.

Nine unit tests cover the keying rule and the deduplication, including the album-5 /
track-5 case that the old key could not tell apart.
