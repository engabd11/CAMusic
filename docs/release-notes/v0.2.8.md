v0.2.8 — artist and playlist screens, one backend at a time
Debug build of Sendspin for Android (work in progress).

## Install
1. Download **sendspin-0.2.8-debug.apk** below onto your Android device (Android 12 / API 31+).
2. Allow **install from unknown sources** when prompted.
3. Open the APK. Installs over 0.2.x (versionCode 13).

Signed with the same key as 0.2.7 and everything before it, so it updates in place
with no uninstall.

## What's new since v0.2.7

### Artist and playlist detail screens

The gap v0.2.7 named: artist and playlist were still in review then, and album was
the only detail screen. Both are here now, and all library navigation is wired to
them — from the cover grid as well as the row list, which previously only routed
from one of the two.

Tapping the artist on an album used to open a broken screen. The album passed its
subtitle — a display name — where an artist id belonged, and the search fallback the
comment described did not exist, so the screen reliably showed "Failed to load
artist". The route now carries the name explicitly and resolves it through search
once, and a joined credit ("Wilco, Billy Bragg") links to the first name.

### One backend at a time

Music Assistant and Navidrome could both hold the speaker at once. Every local
playback entry point now tells MA to let go first — including the album screen,
which was the last one outside the rule and the screen albums actually get started
from. Adding to a queue is deliberately left alone: appending is not taking over.

### The Navidrome path on the new screens is a real queue

The artist and playlist view models claimed the album screen's dual-backend pattern
without following it — every action fell through to a queue of one. Play on a
playlist played track one and stopped, Shuffle played track one and did not shuffle,
downloaded copies were ignored in favour of the stream, and Add to queue answered
"Queue management needs Music Assistant" while `LocalPlayer.addToQueue` sat right
there. This is the backend whose whole point is working with MA switched off. Both
now resolve tracks through the download index so offline copies win, shuffle before
building the queue so the order is actually shuffled, and start the list from the
track you tapped rather than replacing it.

### Opening the app no longer stops the music

The mutual-exclusion stops were running from `applyBackend()`, which also fires on
every activity creation — and the command waits up to 5s for the socket rather than
failing fast, so the stop landed even on a cold start. Opening the app while MA was
streaming to the phone stopped playback. The stops now fire only on a real backend
switch.

Three audio-focus fixes came with it: a permanent focus loss pauses instead of
throwing away the queue you built, a transient loss resumes when focus comes back
rather than leaving the music dead after a call, and running off the end of the
queue abandons focus so other players stop being held down by a finished session.

## Known gaps
- Dragging a queue row to the very edge of the list still doesn't auto-scroll; long
  moves need two drags.
- The artist screen resolves an artist by searching for its name, because library
  items carry artist names and no artist ids. An artist whose name doesn't match
  what search returns won't resolve.
