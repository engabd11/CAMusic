v0.4.3 - the Material 3 window, and lyrics that keep up
Debug build of Sendspin for Android (work in progress).

## Install
1. Download **sendspin-0.4.3-debug.apk** below (Android 12 / API 31+).
2. Allow **install from unknown sources**, then open it. Installs over 0.4.x (versionCode 26).

Two fixes on top of [v0.4.2](v0.4.2.md). Nothing else changed.

## The XML window theme is Material 3

The Material 3 upgrade was finished everywhere except the one place Compose cannot
reach: the window itself.

PR #22 added `com.google.android.material` for the express purpose of using
`Theme.Material3.NoActionBar` as the XML theme parent, then reverted the parent when a
CI runner restoring a Gradle cache from before that dependency existed failed to
resolve it. The library stayed; its reason for being there did not. The dependency has
since been on master through several green runs, so the obstacle has expired.

Parented on **`Theme.Material3.Dark`** rather than `DayNight`, because the app is
OLED-black in every mode and a DayNight parent hands the window light defaults to
override in light mode.

This is the theme that paints the window *before* Compose draws, so it is where a
Material/Material3 mismatch shows up: as a wrong-coloured flash on cold start.

**Worth a look:** launch the app cold (swipe it away first) in both light and dark
system modes and watch the first frame. It should go straight to black.

## Synced lyrics

Reported as "not synced properly, and completely lost after seeking". Two separate
causes, and the lyrics pane was innocent of both - it picks the active line straight
from the playhead and always did that correctly.

**Not synced properly.** The local player published its position every 500 ms. That is
fine for a progress bar and too coarse for a lyric: a line could light up a beat after
it was sung, every time. It ticks at 250 ms now, the same rate the Music Assistant path
already used.

**Lost completely after seeking.** That was the scroll animation, not the sync. Seeking
moves the playhead by minutes, so the active line jumps by tens of rows, and the pane
animated the entire distance. While it travelled, the highlighted line was nowhere near
the screen. A jump of more than four lines now goes there at once; only the ordinary
line-to-line advance is animated.

**Worth a look:** a Navidrome track with synced lyrics - does the highlight sit on the
beat rather than behind it, and does scrubbing land the right line immediately?
