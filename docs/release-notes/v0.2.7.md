v0.2.7 — album detail screen and Navidrome as a real backend
Debug build of Sendspin for Android (work in progress).

## Install
1. Download **sendspin-0.2.7-debug.apk** below onto your Android device (Android 12 / API 31+).
2. Allow **install from unknown sources** when prompted.
3. Open the APK. Installs over 0.2.x (versionCode 12).

Signed with the same key as 0.2.6 and everything before it, so it updates in place
with no uninstall.

## What's new since v0.2.6

### Album detail screen

Opening an album used to drop you into the same flat track-list browse node as any
other folder. There is now a dedicated screen: large centred artwork with a
palette-derived glow, the album title, accent-coloured artist, and a metadata line
(year · genre · track count · total duration), with Play, Shuffle and Add to Queue
built from the existing OLED design-system components.

### Navidrome is a standalone backend now

Switching the library backend *looked* like it did nothing, because nothing
re-derived the library's state after the switch. Readiness for the Music Assistant
backend was only ever set inside `maApi.state.collect`, so going Navidrome → MA
while the socket was already connected waited on a StateFlow transition that never
arrived — the library sat on its skeleton forever, and that direction of the toggle
was permanently dead. `setBackend` also cleared the browse stack but not the node,
shelves or favourites, so the old backend's content stayed on screen under the new
backend's name. `applyBackend` now drops everything derived from the old backend and
re-derives readiness from current state instead of waiting on an edge.

Everything the Navidrome path needed to actually be usable came with it:

- **Errors say what went wrong.** `SubsonicClient` throws with the server's own
  message instead of returning an empty list, so a wrong password, an unreachable
  host and a genuinely empty library stop looking identical. It also gained genres,
  starred, albums, random, `getSong`, star/unstar, scrobble and playlist search, and
  reads the OpenSubsonic format fields for the quality badge.
- **Address scheme is inferred.** A scheme-less address defaults to `http` for a LAN
  box and `https` for a public hostname. The old https-always default simply could
  not reach a self-hosted server, and flipping the default the other way would have
  put credentials in the clear.
- **The local player is a real queue.** `LocalPlayer` gained shuffle, repeat, seek,
  reorder, auto-advance and speed instead of a one-shot `play(url)` — playing an
  album used to mean playing its first track and stopping, which made downloads
  pointless. It is hoisted to `SendpinApp` so it is process-scoped, with a new
  `LocalPlaybackService` for lock-screen and Bluetooth controls, and it is wired into
  Now Playing so the transport, queue and scrubber follow whichever player holds the
  session.
- **Downloads take a whole album, playlist or artist** in one sequential job, and
  cache cover art alongside the audio. Covers used to vanish the moment the server
  did — which is exactly when downloads are meant to be used.
- **Offline mode.** With the server unreachable the library browses and plays from
  disk instead of showing a connect form it cannot use.
- **The Navidrome server is editable from Settings.** It was reachable only from the
  Library connect form, which is hidden once a connection works — so a moved server
  or a changed password could not be fixed in the app at all.

Two hot-path defects in that new code are fixed here too: `LocalTrack.offline` no
longer stats the disk on every state emission, and the media notification is rebuilt
on play/pause rather than on every 500ms position tick.

## Known gaps
- The Navidrome backend is verified by compile and unit tests (38 pass), but has
  **not yet been run against a live Navidrome server**. Please report what breaks.
- Artist and playlist detail screens are not in this build — they are still in review
  on PR #11 and will land in the next release. Album is the only detail screen so far.
- Dragging a queue row to the very edge of the list doesn't auto-scroll; long moves
  need two drags.
