v0.3.0 — the artist crash actually fixed, badges fixed on both surfaces
Debug build of Sendspin for Android (work in progress).

## Install
1. Download **sendspin-0.3.0-debug.apk** below onto your Android device (Android 12 / API 31+).
2. Allow **install from unknown sources** when prompted.
3. Open the APK. Installs over 0.2.x (versionCode 15).

Signed with the same key as 0.2.9 and everything before it, so it updates in place
with no uninstall.

## What's new since v0.2.9

Re-testing 0.2.9 on a device showed that three of the eight fixes it claimed were
not actually holding. This release fixes them properly — the earlier attempts had
the wrong root cause, the wrong file, or a comparison that could never be true.

### The artist crash, for real this time

0.2.9 blamed a `genreList` cast. That was not it: `loadArtist()` wraps every parse in
`catch (Exception)`, so a `ClassCastException` there surfaces as the screen's error
state and never reaches a crash — and the same object had already parsed once to draw
the library row.

The real crash is in composition. The artist screen put top tracks and albums in
**one** `LazyColumn` keyed on a bare `itemId`, and Music Assistant numbers library
items per media type — so a track and an album can both be item 7. A duplicate key
is a hard `IllegalArgumentException` in a lazy list, which is exactly why it hit some
artists and not others.

Keys are namespaced by section and index on the artist, album and playlist screens.
MA also answers `artist_albums` and `top_tracks` per provider mapping and
concatenates the results, so those lists are de-duplicated by id — an artist held by
two providers was listing every row twice.

### Source badge, on both surfaces

0.2.9's fix was applied to the Now Playing screen only. The overlay kept the old
blank-check and the raw provider string, so nothing changed at all for anyone using
overlay mode. The "always shows" rule now lives in the view model's state, which no
longer goes blank, and both surfaces simply render it — they can't drift apart again.

### Quality popup's Source row

The row was meant to hide when Source matched Playing. It never did, because Playing
is read from the queue's stream details (which carry a bitrate) and Source from
`provider_mappings.audio_format` (which has no bitrate field) — so the two labels
could never be equal, and the row always showed. The comparison is on codec, sample
rate and bit depth now.

### Artist buttons worked on nothing under Navidrome

The Play / Shuffle / Add to Queue set added to the artist hero in 0.2.9 acted on top
tracks, which are always empty on Navidrome — the buttons were silently dead on that
backend. They act on the artist's whole catalogue now, and say so when there is
nothing to play.

### Parsing and cleanup

`strList` and `artistString` had the same unguarded field access that `genreList`
did; all three now go through one safe reader, covered by a new parse-shape test
suite. The unit tests are up from 38 to **47**. Code left dead by 0.2.9 —
`sleepTimerPresets`, `shuffleTopTracks()` — is removed.

The branch APK workflow now runs the unit tests too. `assembleDebug` on its own never
compiles the test sources, so a branch could go green with broken tests.

## Known gaps
- Dragging a queue row to the very edge of the list still doesn't auto-scroll; long
  moves need two drags.
- The artist screen resolves an artist by searching for its name, because library
  items carry artist names and no artist ids. An artist whose name doesn't match
  what search returns won't resolve.
