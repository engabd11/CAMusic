v0.6.0 - a player that exists, downloads that obey you, and cleartext that stays home
Stable build of CAMusic for Android.

## Install
1. Download **camusic-0.6.0.apk** below (Android 12 / API 31+).
2. Allow **install from unknown sources**, then open it. Installs over 0.5.x (versionCode 28) — same signing key, so your servers, credentials and downloads survive.

## Now Playing opens on a player that exists

The target preference is blank by default, blank means "this phone", and this phone is
only a Music Assistant player once it has finished registering. On a first run — or with
the player disabled — the whole screen addressed an id MA had never heard of. Every
transport control did nothing, and the only way to start music was to open Speakers and
pick a player by hand.

Your choice is still honoured when it names a player that exists. Otherwise it falls
through: this phone if MA knows it, then the first *available* player, then whatever is
left. Availability before position, because falling back to a speaker that is itself
offline only moves the dead end. The preference is never rewritten, so once the phone
registers it takes back over on its own.

## Cleartext stays on the local network

The app sends a Music Assistant password, a Navidrome password and a Home Assistant
long-lived token. Over `http://` those cross the network in the clear. On a home LAN that
is a considered trade — nobody runs TLS on their NAS. To a host out on the internet it is
a disclosure to every hop in between, and until now nothing told the two apart.

Requests now refuse to leave in the clear unless the address is local: loopback and the
private ranges, carrier NAT, link-local, any single-label host, and the usual home
suffixes (`.local`, `.lan`, `.home`, `.internal`). Everything else must use TLS, and the
refusal names the host and says what to do about it.

The app also no longer trusts user-installed certificate authorities. Android has ignored
them by default since API 24 because they are an MITM vector, and the one case they
enabled — self-signed TLS on a LAN box — already has a plain answer here.

## Downloads obey their own settings

**Wi-Fi-only** and the **storage cap** were both in Settings and neither did anything.
Wi-Fi-only is now checked when each file starts rather than once for the batch, so a
download that begins on Wi-Fi and continues on mobile data stops. The storage cap deletes
the oldest downloads once the total passes it.

## Background connection is a choice

**Settings → Sendspin player → Announcements.** On by default: the phone stays reachable
so Home Assistant can speak to it. Off releases the connection, the wake lock, the wifi
lock and the ongoing notification once playback is idle — the whole background cost of
the app, for anyone who never sends an announcement to their phone.

Playback is unaffected either way. Music started on the phone keeps playing when the app
is backgrounded.

## Also

- **MA's output limiter** is a switch in the DSP sheet. It was modelled nowhere and
  described in a line of prose that said it existed and was on by default.
- The **onboarding screen and boot splash** show the mushroom rather than a letter "S"
  left over from the old name.
- The **baseline profile** is regenerated against this build.
- A **crash on mDNS discovery** when a service is found after discovery has failed.
- Proguard keeps no longer hold media3 and Coil whole, which had disabled shrinking
  across the two largest dependencies to restate rules those libraries already ship.
