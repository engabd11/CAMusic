v0.3.4 — registering on enable, honest codec names, and three UI fixes
Debug build of Sendspin for Android (work in progress).

## Install
1. Download **sendspin-0.3.4-debug.apk** below (Android 12 / API 31+).
2. Allow **install from unknown sources**, then open it. Installs over 0.3.x (versionCode 19).

## What's new since v0.3.3

### Registering happens when you enable the player

The separate "Register again" button is gone. **Enable player** now compares the name
you typed against the name this player was last registered under, and mints a new
identity itself when they differ — so changing the name and enabling is all there is
to it.

The bogus "Music Assistant hasn't registered this player yet" is also gone. It fired
after a rename that had plainly worked: the check exists only to decide whether a
follow-up config write is worth attempting, and a freshly-registered player already
carries the right name from the hello. It has nothing to complain about.

### Codec names, and remote players

An MP3 reported as "MPEG". Music Assistant reports a track's `content_type`, which is
the container or MIME name rather than the codec anybody would recognise — `mpeg` from
`audio/mpeg`, `ogg` for Vorbis, `m4a` for AAC. Uppercasing that verbatim is what
produced "MPEG". Those are mapped to the names people use now.

**Remote speakers reported this phone's format.** When the target was another speaker
and Music Assistant hadn't reported stream details, the badge fell back to this
phone's own output ceiling — claiming every speaker played whatever this phone would
have. A remote speaker decodes on its own hardware and MA is the only thing that knows
what it was handed, so that fallback is gone: the badge shows what MA reports, or
nothing. The same fallback is gone from the self case, which is why Settings and the
badge now always agree.

### Swiping up no longer moves the player

Swiping up lifted the whole cover a little as a "hint" before the queue appeared. It
read as the screen jumping. The cover now stays exactly where it is and only the queue
comes up over it; the upward travel is still measured, it just doesn't move anything.
Swiping *down* to minimise is unchanged.

### The speaker popup is one layer again

"Manage groups" is gone from the output picker. Grouping and sync offsets live on the
Speakers tab; a second route in from a popup was just another line to read past.

### The album art stops resizing

Tapping the quality badge visibly shrank the artwork behind it. The detail card was a
*focusable* popup, and taking window focus puts the activity through its soft-input
resize path. It no longer takes focus — the scrim closes it, and Back is handled
directly.

## Still open

**Adding to the queue on the Music Assistant player.** The Commands Reference PDF is a
print of the collapsed page: every command shows its name and one-line summary with
the parameter table hidden behind the ▼, so there are no argument details in the file
to work from. Rather than guess at it a fourth time, this release leaves the call as
it is. An expanded copy of that page — or the browser's JSON from
`/api-docs/commands` — would settle it in one go.

**A queue that repeats its last track** is not yet diagnosed; see the notes on the
issue.
