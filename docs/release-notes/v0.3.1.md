v0.3.1 — a solid timeline, a name that sticks, and colours that are actually on the cover
Debug build of Sendspin for Android (work in progress).

## Install
1. Download **sendspin-0.3.1-debug.apk** below onto your Android device (Android 12 / API 31+).
2. Allow **install from unknown sources** when prompted.
3. Open the APK. Installs over 0.3.x (versionCode 16).

Signed with the same key as 0.3.0 and everything before it, so it updates in place
with no uninstall.

## What's new since v0.3.0

Fourteen issues from device testing, plus stream-format selection for both backends.
The position engine is the substantial one; the rest are independent.

### Seeking, skipping and the timeline

This is the headline. The hand-rolled position engine is replaced by a port of
`PlayerPositionTracker` from the official Music Assistant app
([music-assistant/mobile-app](https://github.com/music-assistant/mobile-app)). Three
properties it has that the old one didn't:

**An optimistic freeze.** A seek or a skip drops an anchor and then *stops accepting
server readings for it* until audio is confirmed. Music Assistant keeps reporting the
outgoing track's position for a beat after a skip, and the old engine dutifully
rendered it — the bar jumped backwards, then forwards again. Every freeze is paired
with a watchdog, so a server that never catches up costs a stuck second rather than a
stuck bar.

**A staleness gate**, on a field this app never parsed: `elapsed_time_last_updated`.
For a remote speaker, Music Assistant reports whatever it last scraped from that
provider, so `elapsed_time` alone says nothing about how old it is — two polls a
second apart can carry the same number. The old engine stamped every reading with
"now" at parse time, which made however stale the reading was into a permanent
offset, and *re-applied it on every poll*. It never converged. That is why the bar
ran behind on another speaker and the next song started while the screen still
showed the last one.

**A play/pause snapshot**, so time spent paused no longer folds into the next forward
step. Time is measured with `elapsedRealtime` rather than the wall clock, so an NTP
correction mid-track can't jump the bar.

The rarer stall — the queue moves on but Now Playing doesn't, until you pause and
play — had four more contributors, all fixed:

- `refresh()` had no ordering and fired from four places at once, so a slow earlier
  response could land after a newer one and pin the UI to a finished track. It is now
  serialised, with requests arriving mid-flight collapsing into a re-run rather than
  being dropped.
- A dropped socket completes pending requests with `null`, which parses to an empty
  list — and adopting that blanked the player mid-track while the sticky title stayed
  on screen. Empty results are now refused while the socket is down.
- Track changes were undetectable when the server omitted `queue_item_id`. There is
  now a title/artist/duration fallback.
- The event stream used `debounce(150)`, which only emits after a gap of silence.
  Music Assistant pushes `queue_time_updated` roughly once a second, which starved it
  completely — leaving the 5-second poll as the only refresh. It samples now.

Light Sync does not read this app's position (it follows a Home Assistant
`media_player` entity backed by the same Music Assistant clock), so the two were
desyncing together as symptoms of one upstream staleness. A solid timeline here is
the fix for both.

### The player's name now sticks

Renaming the player still read back as the phone's model. The hello only *registers*
a name — after that, Music Assistant's per-player config decides the displayed one
forever, and nothing in this app ever wrote it. Renames now go through
`config/players/save` with `values.name`, which is exactly what both reference
clients do, and take effect without a reconnect.

`device_info` no longer carries `Build.MODEL` / `Build.MANUFACTURER` either. The
official app announces `"Mobile Application" / "Music Assistant"` and massdroid
announces `"Mobile Application" / "asksakis.net"`; sending the hardware there is part
of why a rename never showed.

### Stream format is selectable, on both backends

**Music Assistant player** — Auto / FLAC / PCM / Opus, in the same Settings card as
the player's name, because both are announced in the same hello. Naming a codec
narrows the advertised format list to that codec alone, which is the only thing that
actually makes the server's choice deterministic: the server may only stream a format
the client listed. This is the same lever the official app pulls. The choice is also
pushed to Music Assistant as `preferred_sendspin_format`, so its own per-player
setting agrees.

**Navidrome** — Original / FLAC / MP3 320 / MP3 192 / Opus 128. The app used to pin
`format=raw` with no way to change it, and the badge always read PCM because that is
the phone's own output. Downloads still always take the original file.

### The media notification stops flickering

The Sendspin server ends the stream between *every* track, and that was wired
straight to `stopService` — so a skip tore the notification down, released the media
session, dropped the cached artwork, and rebuilt all of it a second later. It now
holds for a minute and cancels the countdown on the next stream. The timer lives
inside the service, because a `stopService` from outside can't be taken back. The
local player gets the same grace.

### Album colours

Most covers fell back to gold, including colourful ones. Two causes, compounding:

The clustering was seeded along the *lightness* axis alone, so k-means converged to
brightness bands rather than colour groups — a cover's red and its blue landed in one
cluster whose mean is grey. And each cluster was represented by its arithmetic mean,
which pulls any mixed cluster toward grey regardless. Colours that were plainly on
the cover never survived to be ranked.

Then everything called "neutral" was warm (`1.0, 0.84, 0.60`), and the accent step
forced saturation to at least 0.50 — turning a grey with a faint warm cast into vivid
amber. That is the gold.

Now: k-means++ seeding in full CIELAB, cluster representatives taken from the most
chromatic quarter of their members rather than the mean, an accent threshold adaptive
to the image's own chroma (so a muted sleeve keeps its muted colours and a neon one
doesn't promote everything), hue-diverse selection so a three-colour cover yields
three hues, and a saturation floor that only applies when there is real chroma to
floor. A genuinely monochrome sleeve now reads as soft silver instead of gold.

### Everything else

- **The overlay no longer covers the bottom of a page.** In overlay layout the mini
  player sits above the tab bar and nothing reserved room for it, so the last row of
  every scrollable screen was hidden behind it.
- **The seek magnifier shows its time.** The bubble is a child of the slider's fixed
  18.dp box, which capped its height — the text was clipped to an 8.dp band and read
  as underscores.
- **Seeking while paused stays paused.** Music Assistant's `players/cmd/seek`
  resolves into `play_index` and starts the queue; it is now re-paused when that was
  the state you were in.
- **The quality popup shows Source on Music Assistant.** Playing and Source were both
  fed from the queue's stream details — literally the same object — and the "hide
  Source when it matches Playing" rule then dropped the row on every track. Source now
  prefers the library file's own format, and both rows always render with a
  "Transcoded…" or "Direct — no transcoding" line beneath.
- **No bounce when you swipe up to the queue.** The queue was set *after* awaiting a
  200 ms slide back down, and the live drag offset was an `Animatable` written from a
  coroutine per pointer sample — its mutex cancelled each sample with the last, which
  is the jitter on top.
- **The speaker chip opens a picker** instead of collapsing the player and switching
  tabs (which did nothing at all on the Navidrome backend, where that route is
  disabled). Switch output and set that speaker's volume without leaving the player;
  grouping is still one tap further on.
- **The library loads.** It was one request for 5000 items against a 30-second
  deadline, on a socket shared with everything else — a large collection simply ran
  out of time and showed "Request timed out" with nothing on screen. It now reads 500
  at a time with a 60-second deadline and two retries, publishing each page as it
  lands, so the first results appear almost immediately.
- **Long-press a track** for Play next / Add to queue. Tapping a row has always meant
  "play this now", which replaces the queue, so queueing one track had no gesture.
  The single-track enqueue paths that silently did nothing on the local player work
  now too.

## Verification

Full `assembleDebug` clean; 74 JVM unit tests pass, including 9 new ones covering the
position tracker (a freeze ignores stale echoes; pausing doesn't fold in wall time;
the projection caps at the duration) and 7 covering colour extraction (a three-colour
cover yields three distinct hues; a small vivid splash leads over a large dull field;
a grey cover stays grey and never lands in the amber band; extraction is
deterministic).

The visual fixes — the magnifier, the swipe, the colours, the speaker picker — are
not reachable from the test suite and were verified by inspection only.
